# Серверный режим MemuAI

Серверный режим — полностью опциональная возможность MemuAI 4.5: MemuAI
подключается к **своему** серверу, а файлы, проекты и чаты живут на
сервере. По умолчанию режим выключен, и MemuAI работает как раньше —
только на этом компьютере.

Образец: Hermes Agent / OpenAI Dots / Claude Duet / Muse. Отличие
MemuAI: один владелец, никаких многопользовательских областей и никакого
чужого облака — сервер ваш, токен ваш, данные ваши.

## Как это устроено

```text
┌──────────────────┐   HTTPS + Bearer   ┌─────────────────────────────┐
│  MemuAI (клиент) │ ──────────────────► │  MemuAI Server              │
│  Настройки →     │   только с токеном  │  Proxy create_app +         │
│  Сервер          │                     │  /api/server/* (файлы,     │
│                  │                     │  проекты, чаты, очередь    │
│  ┌────────────┐  │   мост: опрос       │  моста)                     │
│  │Local Bridge│◄─┼──────────────────── │  ИИ работает с файлами     │
│  └────────────┘  │   очереди моста     │  СЕРВЕРА («свой компьютер»)│
└──────────────────┘                     └─────────────────────────────┘
```

* **Сервер** — отдельный процесс `memuai_server.py` на базе существующего
  FastAPI-приложения MemuAI Proxy (`app/main.py:create_app`). Серверный
  API монтируется поверх него (`app/server_mode/router.py`); маршруты
  Proxy не меняются.
* **Клиент** — раздел «Сервер» в настройках MemuAI: адрес, токен, режим,
  переключатели синхронизации, статус, мост.
* **Мост** (`app/local_bridge/`) — локальный агент на компьютере
  пользователя. Серверный ИИ **никогда** не обращается к компьютеру
  пользователя напрямую: его запросы попадают в очередь на сервере, мост
  опрашивает очередь, проверяет политику, спрашивает пользователя и
  только потом выполняет — и возвращает результат на сервер.
* **Синхронизация** — push/pull между локальными корнями и сервером на
  уровне API-клиента (`app/server_mode/client.py`) с манифестами,
  конфликтами и офлайн-очередью.

## Режимы

| Режим | Где данные | Что делает ИИ |
|---|---|---|
| **Локально** (по умолчанию) | Только на этом компьютере | Как раньше, сервера нет |
| **Сервер** | На сервере | Работает с файлами сервера |
| **Гибрид** | И локально, и на сервере | Синхронизация по переключателям ниже |

Переключатели синхронизации — проекты, файлы, чаты — по умолчанию
выключены. Синхронизация запускается кнопкой «Синхронизировать сейчас»;
переключатель «автоматически» сохраняется как настройка, но фоновый
планировщик в этом раунде ещё не подключён (см. «Ограничения»).

## Токен

* При первом запуске сервера токен генерируется (`secrets.token_urlsafe`)
  и записывается **только на сервере**: `<каталог данных сервера>/server_token`,
  права 0600. Сам токен нигде не печатается и не логируется — процесс
  показывает только путь к файлу и маску (`••••` + 4 символа).
* Без токена доступа нет: любой запрос к `/api/server/*` без заголовка
  `Authorization: Bearer <токен>` или с неверным токеном получает 401.
  Сверка — `hmac.compare_digest` по SHA-256 дайджестам.
* На клиенте токен хранится **только** в защищённом хранилище: Windows —
  DPAPI, остальные ОС — шифрованный файл из `app/dfy_vault.py`. В
  настройках видна только маска; в файл настроек токен не попадает.
* Потеряли токен — удалите файл `server_token` на сервере и перезапустите
  его: создастся новый. Старый перестанет работать. Клиенту введите новый
  токен в Настройки → Сервер.

## Запуск сервера

### Windows

```powershell
cd E:\MemuAI
.\.venv\Scripts\python.exe memuai_server.py --port 8327
```

Сервер слушает `127.0.0.1:8327` по умолчанию. Для доступа извне — только
за reverse proxy с HTTPS (ниже) и с флагом `--allow-remote`:

```powershell
.\.venv\Scripts\python.exe memuai_server.py --host 127.0.0.1 --port 8327 --allow-remote
```

Без `--allow-remote` привязка к не-loopback адресу отклоняется.

Каталог данных сервера: `MEMUAI_SERVER_DATA_DIR` или
`<данные MemuAI>\server`. Переменные окружения: `MEMUAI_SERVER_HOST`,
`MEMUAI_SERVER_PORT`, `MEMUAI_SERVER_DATA_DIR`.

### Linux

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
MEMUAI_SERVER_DATA_DIR=/var/lib/memuai-server \
  .venv/bin/python memuai_server.py --host 127.0.0.1 --port 8327 --allow-remote
```

Для постоянной работы — systemd: `packaging/server/memuai-server.service`
(скопируйте в `/etc/systemd/system/`, поправьте пути и пользователя,
`systemctl enable --now memuai-server`). В Docker — `packaging/server/Dockerfile`.

### Reverse proxy (HTTPS — обязательно для доступа извне)

Пример для nginx — `packaging/server/nginx.conf.example`. Суть:

* `listen 443 ssl`, сертификат от Let's Encrypt (certbot), не
  самоподписанный;
* `proxy_pass http://127.0.0.1:8327;` с пробросом `Host`,
  `X-Forwarded-For`, `X-Forwarded-Proto`;
* `client_max_body_size 100m;` (лимит загрузки файлов на сервере);
* сервер MemuAI при этом по-прежнему слушает только loopback.

Самоподписанные сертификаты в коде не создаются и не используются.

## Настройка клиента

Настройки → Сервер:

1. Выберите режим («Сервер» или «Гибрид»).
2. Введите адрес сервера и токен (токен — из файла `server_token` на
   сервере; вводится один раз).
3. «Проверить соединение» — сервер должен ответить 200.
4. Включите нужные переключатели синхронизации.
5. Индикатор: точка рядом с кнопкой «Настройки» — зелёная при подключении,
   красная при включённом режиме без подключения; в режиме «Локально»
   точки нет.

## Мост к компьютеру пользователя

Мост выключен по умолчанию. Когда включён:

* **Разрешённые папки** — только внутри них мост читает, пишет и запускает.
  Вне их — ничего, никогда.
* **Классы действий** — отдельные переключатели: чтение, запись, запуск,
  браузер. Каждый класс выключен по умолчанию, кроме чтения.
* **Allowlist команд** — явный список (`git`, `python -m pytest`,
  `pytest`, `node`, `npm`, `cargo`, `go` и только разрешённые
  подкоманды/флаги). Выполнение — только списком аргументов, без
  `shell=True`, без подстановок, без shell-метасимволов. Скрипты — только
  внутри разрешённых папок.
* **Подтверждение** — «Каждый раз» или «Один раз на действие» (одно
  одобрение на класс + область запоминается до перезапуска). Без
  подтверждения запрос висит в статусе ожидания в разделе «Сервер» —
  кнопки «Разрешить» / «Запретить».
* **Браузер** — мост только авторизует открытие публичной http(s)-ссылки;
  открывает её браузер MemuAI. Приватные адреса (localhost, LAN) запрещены.
* **Журнал** — каждый вызов: время, класс, цель, статус, длительность.
  Значения, похожие на секреты, в журнал не попадают.
* **«Отозвать доступ»** — один клик: мост мгновенно отключается, очередь
  ожидания очищается, новые запросы отклоняются. Включается заново только
  переключателем в настройках.

Серверный ИИ работает со «своим компьютером» — файлами сервера. К
компьютеру пользователя — только через мост и только с разрешения.

## Синхронизация и конфликты

* Сравниваются манифесты (SHA-256, размер, время): изменилась одна
  сторона — её версия переносится; не изменилось ничего — пропуск.
* Изменились обе стороны — **конфликт**. Правило: побеждает более новая
  версия (`mtime`); при равном времени MemuAI не перезаписывает молча —
  конфликт остаётся и требует явного выбора («локальная» / «серверная»).
  Слияния содержимого нет.
* Нет соединения — операции попадают в офлайн-очередь
  (`offline_queue.json` в папке синхронизации) и применяются по порядку
  при появлении соединения; при первой же ошибке очередь останавливается
  и остаток сохраняется.
* Лимит одного файла на сервере — 100 МБ.

## API сервера (кратко)

Все маршруты — только с `Authorization: Bearer <токен>`:

| Маршрут | Что делает |
|---|---|
| `GET /api/server/health` | Проверка, версия сервера |
| `GET /api/server/manifest` | Манифесты файлов, чатов, проектов |
| `GET/PUT/DELETE /api/server/files/{путь}` | Файлы (путь — только внутри `files/`) |
| `GET/PUT/DELETE /api/server/chats/{id}`, `.../projects/{id}` | Документы чатов/проектов (JSON) |
| `POST /api/server/bridge/requests`, `GET ...?status=pending`, `POST .../{id}/result` | Очередь моста |

## Ограничения этого раунда

* Один владелец; многопользовательских областей, квот и ролей нет.
* Синхронизация чатов/проектов реализована на уровне API и манифестов;
  полная синхронизация содержимого локальных `chats.json` /
  `workspaces.json` в интерфейс не встроена — переключатели управляют
  файловой синхронизацией и готовностью API.
* Мост опрашивает очередь по кнопке «Проверить очередь моста» в
  настройках; постоянного фонового опроса и автосинхронизации по
  расписанию в этом раунде нет — переключатель «автоматически»
  сохраняется, но планировщик ещё не подключён.
* Действие «браузер» выполняется браузером MemuAI на хосте; сам мост
  ничего не открывает.
* Проверка HTTPS, сертификатов и настоящего reverse proxy — только на
  реальной установке (пример конфига прилагается); в тестах — localhost.
* Полный Proxy (`create_app` со всеми провайдерами) в проверочной среде
  не запускался: не хватило места для тяжёлых зависимостей. Серверный
  роутер проверен end-to-end на localhost в двух процессах через тот же
  код `memuai_server.build_server_app` с фабрикой приложения-заглушки;
  монтирование на настоящий `create_app` проверено только статически
  (см. отчёт раунда у координатора).
