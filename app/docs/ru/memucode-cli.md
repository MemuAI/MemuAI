# MemuCode CLI

**MemuCode CLI** — тот же агент для программистов, что и [MemuCode](doc:memucode), но в командной строке. Он читает и правит файлы проекта, запускает тесты и сборку в песочнице, ищет в интернете, управляет браузером и рабочим столом, помнит разговоры и умеет откатывать любые правки. Модели берутся из [MemuAI Proxy](doc:proxy), поэтому работают те же аккаунты, что и в приложении, — а по желанию можно подключить API напрямую.

## Установка и запуск

### Из установщика

Полная установка MemuAI ставит и MemuCode CLI: программа лежит в папке `MemuCode` рядом с MemuAI, в меню «Пуск» появляется ярлык **MemuCode CLI**, а папка добавляется в `PATH` пользователя. Откройте новый терминал в папке проекта и выполните:

```
memucode
```

Если снять компонент MemuAI при изменении установки или удалить программу, запись в `PATH` убирается.

### Из исходников

```
python memucode.py
```

Команда `/install` (или `python memucode.py install`) добавляет короткую команду `memucode` в `PATH` пользователя; `memucode uninstall` убирает её. Нужны пакеты `prompt_toolkit`, `rich` и `anthropic` из `requirements.txt`.

## Первый запуск

1. MemuCode ищет запущенный MemuAI Proxy. Если он не отвечает, MemuCode запускает его сам (выключается настройкой `proxy_autostart`).
2. В первый раз предлагается выбрать тему оформления.
3. Для новой папки MemuCode спрашивает, доверяете ли вы ей: только в доверенной папке работают проектные хуки, серверы MCP из `.mcp.json` и проектные настройки.
4. Модель по умолчанию берётся из настроек MemuAI; поменять — `/model` или ++Alt+P++.

Проверить всё разом — `/doctor` (или `memucode doctor` без интерфейса): терминал, Proxy, модели, оболочка, git, песочница, браузер, MCP, цены, модель решений, микрофон.

## Ввод

| Что ввести | Что произойдёт |
| --- | --- |
| обычный текст | задача агенту |
| `/команда` | команда MemuCode, список открывается сразу |
| `@путь` | упомянуть файл или папку — содержимое приложится к запросу |
| `@agent-имя` | поручить задачу суб-агенту |
| `!команда` | выполнить в терминале без модели; вывод попадёт в разговор. Из Telegram Mini App не выполняется — там попросите агента обычным сообщением |
| `#правило` | запомнить правило в файле памяти |
| `&задача` | запустить задачу в фоне, не занимая разговор |

Пока агент работает, можно писать дальше: сообщения встают в очередь и уходят, когда он закончит шаг. ++↑++ возвращает сообщение из очереди на правку. Команды, которые только показывают или задают что-то (`/skills`, `/model`, `/usage`, `/permissions`, `/schedule`…), выполняются сразу, не уходят модели и не прерывают работу; команды, которые начинают новый разговор или меняют папку, ждут конца работы агента.

`@` подсказывает только файлы и папки **проекта** (и папок из `/add-dir`) и никогда не просматривает весь диск. В очень большой папке (профиль пользователя, корень диска) индекс строится в пределах времени и размера и об этом говорит. `/cd` в несуществующую папку предлагает её создать (ответ по умолчанию — «Нет»); `/cd путь --new` создаёт без вопроса.

Картинки: ++Alt+V++ (или ++Ctrl+V++) вставляет изображение из буфера обмена, а путь к файлу картинки, вставленный или перетащенный в терминал, превращается во вложение `[Image #1]`. Длинная вставка текста сворачивается в `[Pasted text #1 +40 lines]` только в поле ввода: при отправке она раскрывается, и в разговоре виден весь вставленный текст. Вставленный путь к папке, к большому или двоичному файлу остаётся обычным текстом пути — без сообщения об ошибке.

++Ctrl+A++ выделяет весь текст в поле ввода, ++Ctrl+C++ копирует выделенное, ++Ctrl+X++ вырезает. Обратная косая черта в конце строки переносит строку, но не после пути Windows и не после команды: `/cd C:\Projects\` отправляется как есть.

Подсказки команд появляются сразу, по мере набора; ++Esc++ закрывает меню и настройки без задержки. Звуков MemuCode не издаёт: о завершении задачи сообщает тихое уведомление Windows. Звонок терминала включается настройкой `notifications` = `bell`, `off` отключает уведомления совсем.

`/effort` задаёт глубину размышлений. Список показывает только уровни текущей модели — те же, что в MemuAI (например, у GLM-5.3 нет «Выкл.», у Gemini 3.7 Flash нет «Минимального»), и строкой о том, что умеет модель; набранный вручную уровень, которого у модели нет (`/effort minimal`), сохраняется и отправляется как ближайший — команда называет, какой именно. Если выбранная модель уровни не поддерживает, значение сохраняется, но на неё не влияет — команда прямо об этом говорит. Подробно — [Модели → Размышления](doc:models).

### Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| ++Enter++ | отправить |
| ++Shift+Enter++, ++Alt+Enter++, ++Ctrl+J++ или `\` в конце строки | новая строка |
| ++Shift+Tab++ | сменить режим разрешений |
| ++Esc++ | остановить агента |
| ++Esc++ ++Esc++ | откатиться к прошлому сообщению (`/rewind`) |
| ++Ctrl+C++ | остановить; на пустой строке дважды — выход |
| ++Ctrl+R++ | поиск по истории запросов |
| ++Ctrl+G++ | написать запрос во внешнем редакторе |
| ++Ctrl+O++ | подробный вывод инструментов |
| ++Ctrl+T++ | список задач агента |
| ++Alt+P++ / ++Alt+T++ | выбор модели / размышления вкл-выкл |
| ++Ctrl+L++ | очистить экран |
| ++?++ на пустой строке | подсказка по клавишам |

++Shift+Enter++ работает в Windows Terminal и обычной консоли Windows без настройки. Для терминала VS Code выполните `/terminal-setup`. Режим Vim включается командой `/vim`.

## Режимы разрешений

| Режим | Поведение |
| --- | --- |
| Обычный | правки файлов и команды, меняющие систему, ждут подтверждения; чтение и поиск — сразу |
| Принимать правки | правки файлов без вопросов, команды — с подтверждением |
| План | только исследование: агент готовит план и предлагает его на согласование |
| Авто | безопасные действия выполняются сами, рискованные спрашивают; риск оценивает модель решений, быстрая модель или встроенные правила |
| Без вопросов | всё выполняется без подтверждения — только для песочниц и одноразовых машин |

Режим меняется ++Shift+Tab++, командой `/mode` (или `/permissions`, где первая строка — выбор режима) или флагом `--permission-mode`. Выбор виден в строке состояния и в коротком уведомлении с пояснением, и **действует во всех окнах MemuCode**: режим, выбранный в одной сессии, остальные подхватывают в течение секунды, а новые — при запуске (`permission_sync` это отключает; окно, запущенное с `--permission-mode`, держит свой). Режим плана — состояние одной задачи и между окнами не передаётся. Опасные команды (форматирование дисков, выключение компьютера и подобное) не выполняются ни в каком режиме.

В режиме **Авто** короткий список однозначных случаев всегда спрашивает вас, что бы ни сказал проверяющий: `git push`, `git reset --hard`, публикация пакета, `sudo`, изменение системных настроек, отправка данных наружу через `curl -d`, запуск скачанного скрипта, чтение или копирование секретов (`.env`, `~/.ssh`, `.aws`), удаление целых папок, кроме остатков сборки (`node_modules`, `dist`…), и запись в `.env`, ключи, `.git`, CI-сценарии и собственные настройки MemuCode. Своё правило (`Bash(git push:*)`) сильнее этого списка.

### Правила

В окне подтверждения можно ответить «да, и больше не спрашивать» — MemuCode предложит правило. Правила пишутся так же, как в Claude Code:

| Правило | Что разрешает или запрещает |
| --- | --- |
| `Bash(npm test:*)` | команды, начинающиеся с `npm test` |
| `Edit(src/**)` | правки внутри `src` |
| `WebFetch(domain:docs.python.org)` | чтение страниц этого сайта |
| `mcp__github` | все инструменты сервера MCP `github` |

Составные команды (`a && b`, `a | b`) проверяются по частям. Правила запрета главнее разрешений. Список и правка — `/permissions`.

## Команды

Полный список — `/help`; `/help команда` показывает подробности. Главные группы:

| Группа | Команды |
| --- | --- |
| Сессия | `/clear`, `/resume`, `/continue`, `/dashboard`, `/resume-claude`, `/resume-codex`, `/resume-grok`, `/resume-gemini`, `/resume-agy`, `/resume-opencode`, `/resume-cursor`, `/rename`, `/branch`, `/rewind`, `/undo`, `/export`, `/copy`, `/todos`, `/auto-continue` |
| Модели | `/model`, `/fast`, `/small-model`, `/vision`, `/effort`, `/think`, `/web`, `/advisor` |
| Контекст и память | `/compact`, `/context`, `/memory`, `/add`, `/image`, `/paste` |
| Работа с кодом | `/init`, `/plan`, `/goal`, `/review`, `/security-review`, `/test`, `/fix`, `/explain`, `/refactor`, `/commit`, `/pr`, `/diff`, `/run` |
| Агенты и инструменты | `/background`, `/tasks`, `/agents`, `/schedule`, `/skills`, `/mcp`, `/browser`, `/computer`, `/search`, `/fetch`, `/decide`, `/loop`, `/tools` |
| Настройки | `/settings`, `/permissions`, `/add-dir`, `/cd`, `/theme`, `/color`, `/lang`, `/vim`, `/output-style`, `/statusline`, `/proxy`, `/import`, `/decisions`, `/hooks`, `/sandbox`, `/notifications`, `/terminal-setup`, `/keybindings`, `/install` |
| Диагностика | `/usage`, `/cost`, `/stats`, `/status`, `/doctor`, `/bug`, `/release-notes` |
| Основное | `/help`, `/help-ask`, `/btw`, `/voice`, `/exit` |

Несколько команд, которые стоит знать:

- `/btw <вопрос>` — быстрый вопрос по ходу дела; агент не прерывается, ответ не попадает в историю.
- `/goal <цель>` — агент работает шаг за шагом, пока цель не будет достигнута или не упрётся в препятствие; `/goal status`, `pause`, `clear`.
- `/background <задача>` — отдельный агент работает параллельно, результат приходит заметкой в разговор; `/tasks` показывает фоновые задачи и команды.
- `/advisor` — вторая, более сильная модель, с которой агент советуется в трудных местах.
- `/model auto` — вы называете несколько моделей на каждый вид запросов (простые, обычные, сложные), коротко пишете, чем каждая хороша, и для каждого запроса MemuCode выбирает уровень, а затем модель, чья заметка подходит лучше; см. [Выбор моделей](#выбор-моделей).
- `/schedule` — запрос, который MemuCode выполняет сам по времени; см. [Задачи по расписанию](#задачи-по-расписанию).
- `/dashboard` — все прошлые сессии в одном списке: свои по всем проектам и, на вкладках, сессии других инструментов; см. [Сессии других инструментов](#сессии-других-инструментов).
- `/import` — перенести MCP-серверы, правила, инструкции, скиллы, команды и сессии из Claude Code, Codex, Grok, Gemini CLI, Antigravity, OpenCode и Cursor.
- `/skills` — менеджер: создать (модель может набросать скилл по описанию), править, выключать и удалять скиллы прямо в терминале.

Свои команды — Markdown-файлы в `.memucode/commands/` проекта или в личной папке `commands`; подходят и файлы из `.claude/commands/`. В тексте работают `$ARGUMENTS` и `$1`…`$9`.

## Модели и подключения

По умолчанию все модели идут через MemuAI Proxy: в `/model` видны модели всех ваших аккаунтов с отметками о зрении, размышлениях и размере контекста. Каждая строка — понятное название, как в MemuAI (ваше переименование, иначе имя из каталога Proxy), а справа приглушённо — полный идентификатор; искать можно и по названию («opus 4.6»), и по идентификатору. После выбора MemuCode пишет «Модель: Claude Opus 4.6 (aws9-…) · контекст …». Модели через Proxy работают с инструментами в текстовом формате, поэтому подходит любая модель.

Команда `/proxy add` подключает API напрямую — Anthropic, OpenAI, OpenRouter или любой совместимый адрес (`/proxy remove` убирает подключение, `/proxy` показывает состояние Proxy и подключения). Такие модели называются `@подключение:модель` и используют нативные инструменты; у Anthropic дополнительно включается кэширование промпта, адаптивные размышления и уровни усилия (`/effort`). Ключи из переменных `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY` подхватываются сами. Старые `/login` и `/logout` убраны.

`/model` ищет по провайдеру и по названию: `/model antigravity` покажет модели этого провайдера, `/model glm` — все GLM, у кого бы они ни были, `/model glm 4.6` сузит список. Одно совпадение выбирается сразу, несколько — открывают список уже с поиском.

## Изображения и модель для изображений

Картинку можно вставить из буфера (++Alt+V++), приложить `/image <путь>` или упомянуть через `@`. Дальше MemuCode решает сам, без вопросов:

1. **Видит ли основная модель картинки?** Он смотрит по четырём источникам, от самого надёжного: что уже выяснилось на деле (картинка прошла или модель отказалась — это запоминается в `vision-support.json` на три недели для отказа и полгода для успеха), что сказано в списке моделей (OpenRouter сообщает входные форматы), что говорит название (Claude, Gemini, GPT-4o и новее, Qwen-VL видят; DeepSeek, GPT-OSS, Llama 3.x — нет) и отметка провайдера. Не знает — **пробует отправить картинку**, и если модель отказывается, запоминает это и описывает картинку вместо неё.
2. **Не видит — переключается на модель для изображений.** Она смотрит на картинку *под задачу основной модели* (ей передаётся ваш запрос), дословно переписывает весь видимый текст и возвращает описание; основная модель получает его текстом вместо картинки. Описание делается один раз и сохраняется в сессии, так что `/resume` и следующие запросы его не повторяют. В ленте одна строка: «◆ модель не видит изображения — их описал …».

Если основной модели нужна подробность, которой нет в описании, она вызывает `Read` для файла картинки с вопросом (`question`), и модель для изображений отвечает именно на него.

Модель для изображений выбирается командой `/vision` и **общая с MemuAI** (настройка «Модель распознавания изображений»): выбрали в одной программе — стоит в другой. Без выбора берётся лучшая из подключённых моделей со зрением (быстрая, не «thinking»).

| Команда | Что делает |
| --- | --- |
| `/vision` | показывает, что происходит с картинками сейчас, и открывает выбор модели для изображений (в списке только модели, которые видят) |
| `/vision <модель>` | выбирает её сразу |
| `/vision auto` | снять выбор: подбирать самому |
| `/vision on`, `/vision off` | включить или выключить описания (выключено — основная модель получит только пометку «было изображение») |
| `/vision test` | **настоящая проверка**: отправляет картинку со случайным кодом основной модели и модели для изображений и смотрит, прочитали ли они его; результат запоминается |

Та же модель работает в **Browser** и **Computer Use**, когда у них нет своей (`/settings` → `browser_model`, `computer_model`) и основная модель слепа. Если выбранная модель вдруг отказывается от картинок, берётся следующая со зрением.

## Выбор моделей

В трёх местах можно назвать **несколько моделей** и написать, чем каждая хороша:

- **`/model auto`** — три уровня: простые запросы, обычная работа, сложная работа. На каждом уровне отметьте одну или несколько моделей. Запрос оценивается по сложности (моделью решений, если она подключена, иначе по ключевым словам) и уходит на нужный уровень; если на уровне несколько моделей, выбирается та, чья заметка лучше подходит запросу.
- **`/agents`** — модели для параллельных агентов. Модель, запускающая агента, может назвать одну (у `Task` есть аргумент `model`), либо выбирает модель решений по задаче агента, либо «всегда первая».
- **`/model notes`** — ваши заметки, по строке на модель («быстрая, хороша с CSS», «медленная, но точная в алгоритмах»). Они хранятся постоянно, видны в каждом списке моделей, их читает тот, кто выбирает, и знает главная модель (заметки входят в её инструкции).

В каждом списке с отметками ++Tab++ отмечает строку (в списке с поиском пробел — это буква), ++Enter++ подтверждает.

## Задачи по расписанию

`/schedule` открывает список задач; быстрая форма — `/schedule daily 09:00 -- проверь упавшие тесты и скажи, что сломалось`. Когда: `in 20m`, `at 15:30`, `every 2h`, `daily 09:00`, `weekdays 09:00`, `mon,fri 18:30` или строка cron `cron 0 9 * * 1-5`. У задачи есть:

- **папка** (проект, где она создана), **модель** и **права**: только чтение, правки файлов проекта (по умолчанию), «Авто» или всё. Во время работы никто не ответит на вопрос, поэтому всё, что режим не разрешает, отклоняется, а отчёт об этом говорит;
- **где запускать**: *в этом окне* (пока открыто окно MemuCode, в систему ничего не ставится) или *в планировщике Windows* (работает при закрытом MemuCode, пока вы вошли в Windows; пропущенный запуск пройдёт при следующем пробуждении компьютера). Запись планировщика лежит в \MemuCode\<id> и удаляется вместе с задачей;
- результаты: ответ сохраняется в `schedule\results\<id>\<время>.md` в папке MemuCode, разговор сохраняется как обычный (`/resume`), показывается уведомление, а `/schedule log <id>` печатает последний результат.

Ещё: `/schedule list`, `run|pause|resume|delete <id>`, и `memucode schedule list` / `memucode schedule run <id>` без интерфейса (именно это запускает планировщик).

## Автопродолжение после лимитов: /auto-continue

Ответ оборвался, потому что у модели кончились лимиты, и ключ пока не работает? `/auto-continue` сам отправит «continue» в этот разговор в назначенное время — сидеть у терминала не нужно.

| Команда | Что делает |
| --- | --- |
| `/auto-continue 18:30` | отправить в 18:30 (если время сегодня прошло — завтра); также `6:30pm`, `tomorrow 09:00`, `завтра 9:00`, `2026-10-12 09:00` |
| `/auto-continue +2h`, `in 45m`, `через 2 часа`, `1h30m` | через указанное время |
| `/auto-continue auto` | когда провайдер снимет лимит: время берётся из его ответа (`Retry-After` и подобные заголовки или текст «try again in 1h2m»); если провайдер его не назвал — через 15 минут, дальше с паузами |
| `/auto-continue 18:30 доделай тесты` | отправить свой текст вместо «continue» |
| `/auto-continue status` · `cancel` · `now` | что назначено · отменить · отправить сразу |
| `/auto-continue` | меню: «Когда сбросится лимит», через 15 мин … 5 ч, завтра в 09:00, своё время |

- Сообщение об ошибке лимита само подсказывает команду и время сброса: «The limit resets at 18:30 (in 1:12:00). /auto-continue auto sends “continue” by itself then».
- Обратный отсчёт виден в строке состояния — «◷ continue in 14:05»; нажатие на него показывает подробности.
- Если и в назначенное время лимит не отпустил, попытка повторяется: в момент, названный провайдером, иначе через 5, 10, 20, 40, 60 минут. Сколько повторов — `--retries N` (по умолчанию 4, `--no-retry` — без повторов, постоянно — `/config set auto_continue.retries 6`).
- `--fallback МОДЕЛЬ` (или настройка `auto_continue.fallback_model`): со второй попытки MemuCode переключается на запасную модель и пишет, как вернуть прежнюю (`/model …`).
- **Окно должно оставаться открытым**: в систему ничего не ставится. План хранится вместе с разговором — если окно закрылось, откройте разговор снова (`/resume`, `memucode -c`), и отсчёт продолжится; если время прошло, пока MemuCode был закрыт, сообщение уйдёт через минуту после открытия (с предупреждением, отменить — `/auto-continue cancel`). Для работы при закрытом окне есть `/schedule` с планировщиком Windows.
- ++Esc++ во время автоматически отправленного запроса отменяет автопродолжение. Ошибка, которую ожиданием не вылечить (неверный ключ, нет модели), останавливает его с объяснением.

## Вопросы о самом MemuCode: /help-ask

MemuCode знает себя: у него есть встроенный скилл-справочник `memucode-guide` — все команды, клавиши, режимы (план, авто…), флаги командной строки, настройки, папки, сессии, агенты, скиллы, MCP, стоимость и Telegram. Справочник собирается из самой программы (реестра команд, списка клавиш, разбора флагов и настроек), поэтому всегда совпадает с ней.

- Просто спросите обычным сообщением: «Как включить в MemuCode CLI планирование?», «какие у тебя горячие клавиши?», «что делает /compact?» — MemuCode узнаёт вопрос о себе, прикладывает справочник к этому ответу (строка «◆ Using the built-in MemuCode guide») и отвечает точными командами (`/plan` или ++Shift+Tab++), а не догадками про флаги запуска.
- `/help-ask <вопрос>` — спросить со справочником наверняка; `/help <несколько слов>` делает то же. Без выбранной модели (или с `--offline`) показываются подходящие строки справочника.
- Отключить справочник можно в `/skills` (как любой встроенный скилл).

## Сессии других инструментов

MemuCode только читает сессии **Claude Code, Codex, Grok, Gemini CLI, Antigravity (agy), OpenCode и Cursor**, найденные на этом компьютере. В их папках ничего не меняется и не блокируется.

- `/resume-claude`, `/resume-codex`, `/resume-grok`, `/resume-gemini`, `/resume-agy`, `/resume-opencode`, `/resume-cursor` — выберите сессию в списке (сначала сессии этого проекта) или назовите её ID: `/resume-claude 3f2a9c добавь регрессионный тест`. По-настоящему продолжить сессию другой программы нельзя, поэтому MemuCode делает то, что сделал бы коллега: пишет **записку о передаче дел** (что просили, чем кончилось, какие файлы тронуты, последние команды и последний обмен), кладёт её в начало нового разговора как *недоверенные данные* и просит модель сверить настоящее состояние (`git status`, файлы), прежде чем продолжать. Текст внутри записки, в том числе похожий на указание, указанием не является.
- `/dashboard` — все сессии: вкладка со своими (по всем проектам) и по вкладке на каждый другой инструмент; открыть, продолжить, импортировать, переименовать, сохранить или удалить.
- `/import` — мастер: показывает, что можно взять (MCP-серверы, правила разрешений, инструкции вроде `CLAUDE.md`/`AGENTS.md`, скиллы, команды, агенты, сессии), вы отмечаете нужное, видите итог, и только потом что-то записывается. Существующее не перезаписывается, секреты на экране маскируются, правила и сессии — только по желанию. Скиллы, команды и агентов Claude Code импортировать не нужно: MemuCode сам читает `~/.claude`.

Cursor читается по описанным форматам и не проверялся на настоящем профиле Cursor; если он ничего не нашёл или показал странное, скажите.

## Стоимость и /usage

`/usage` показывает, сколько потратила сессия: токены по моделям (вход, выход, чтение и запись кэша), время, число запросов, **примерную стоимость**, расход за сегодня и за 30 дней и лимиты ваших аккаунтов из Proxy. Стоимость видна и в строке состояния.

Цены берутся по порядку:

1. ваши цены из `/cost set`;
2. модуль «Каталог моделей» MemuAI, если он установлен и загружен;
3. общий каталог цен OpenRouter (обновляется раз в сутки в фоне, `/cost refresh`);
4. встроенная таблица цен популярных моделей.

Для аккаунтов с подпиской (Genspark, Kiro, Antigravity, Gemini, Grok через Proxy) показывается **эквивалент по ценам API** — сколько бы это стоило по тарифам разработчика; реальные списания здесь — лимиты подписки. Для прямых API считается фактическая стоимость, а OpenRouter сообщает точную сумму сам. `/cost prices` показывает, какую цену и откуда взял MemuCode для каждой модели. Та же оценка есть в карточке **Статистика MemuCode** в приложении.

## Модели решений

*Модель решений* не пишет текст: она отвечает на типизированные вопросы — «да или нет», выбор из вариантов, оценка по шкале — числами за доли секунды. MemuCode задаёт ей вопросы шести видов:

- **режим «Авто»** — насколько рискованна команда или правка;
- **`/model auto`** — насколько сложен запрос;
- **`/agents`** — какая модель возьмёт задачу агента;
- **подсказка скилла** — подходит ли один из скиллов (MemuCode говорит об этом модели и показывает строку);
- **`/goal`** — достигнута ли цель;
- **предложить план** — большая ли это задача (диалог предлагает режим плана, не чаще раза в пять ходов, не в «Авто», с пунктом «больше не предлагать»).

Вопросы об одном запросе задаются вместе, одним обращением на модель и с ограничением в несколько секунд: медленная или упавшая модель решений никогда не задерживает работу.

`/decisions` — меню: **Подключить…** (OpenRouter — один ключ, все модели решений; TypeSafe напрямую — Jev; свой совместимый адрес; или обычная модель, отвечающая в том же формате), **Какая модель решает…**, **Своя модель для каждой проверки…**, **Запасные модели…**, **Для чего использовать…**, **Заметки о моделях решений…**, **Проверить подключение**, **Выключить**. С OpenRouter список читается вживую с `openrouter.ai` (ключ для чтения не нужен, кэш на сутки, без сети — встроенный список), поэтому новые модели — Jev, Kev 4B, Span-01 и Span-01 Lite, Solar Decide, Mercury Decide, Tev1 4B Experimental и всё, что добавят вендоры, в том числе будущие модели ChatGPT, Claude и Gemini, — появляются без обновления. Искать можно по имени, автору или слову «free». Подключение OpenRouter, уже добавленное через `/proxy add`, даёт ключ.

Для лёгких проверок (подсказка скилла) возьмите лёгкую бесплатную модель, для оценки риска в «Авто» — осторожную. Запасные спрашиваются по порядку, когда выбранная не отвечает (не при плохом ключе — он одинаков для всех моделей). Модель, созданная для одного вида вопросов (Span — да/нет, Tev1 — выбор одного), другим не спрашивается, а выбор её для проверки, которой нужно больше, сначала уточняется. `/decisions test` проверяет по очереди каждую используемую модель. Выключение сохраняет настройки (`/decisions on` возвращает их).

Спросить модель решений вручную — `/decide текст ? вопрос`, с вариантами — `/decide текст ? вопрос | вариант 1 | вариант 2`. Что такое модель решений, как читать её вероятности и чего она не умеет — на странице [Модели решений (Decisions)](doc:decisions).

## Сессии, откат и сжатие

Каждый разговор сохраняется в папке данных MemuAI: `-c` продолжает последний, `-r` или `/resume` открывает список с поиском. История только дописывается и никогда не стирается.

Перед каждым ответом агента MemuCode запоминает состояние файлов. `/rewind` (или ++Esc++ ++Esc++) возвращает код, разговор или и то и другое к выбранному сообщению; `/undo` отменяет правки последнего ответа; `/branch` ответвляет разговор, чтобы попробовать другой путь.

Когда контекст заполняется, MemuCode сначала сворачивает старые большие результаты инструментов, а у порога (85% по умолчанию) сжимает историю в сводку. `/compact <на чём сосредоточиться>` делает это вручную, `/context` показывает, чем занят контекст. Для Anthropic повторяющаяся часть запроса кэшируется, повторные чтения неизменённых файлов заменяются короткими ссылками.

## Память, скиллы и агенты

- **Память** — файлы `MEMUCODE.md` (а также `AGENTS.md` и `CLAUDE.md`) в проекте и личный `MEMUCODE.md`. Поддерживается `@путь` для включения других файлов. `/init` изучает проект и создаёт `MEMUCODE.md`, `#правило` дописывает правило, `/memory` открывает файлы.
- **Скиллы** — встроенные скиллы MemuCode, `.memucode/skills/<имя>/SKILL.md`, `.claude/skills/` и личные. Агент подключает подходящий сам; `/имя-скилла` вызывает вручную. `/skills` — менеджер: **создать** (написать самому во встроенном редакторе терминала либо описать словами, и MemuCode набросает черновик, который вы правите; ни в какую другую программу вас не выбрасывает), **править**, **выключать**, **удалять** (в корзину, откуда можно вернуть; встроенные скиллы можно только выключить). Модель знает, как устроены скиллы, где лежат и как удалить, — у неё есть инструмент `SkillManage`, а удаление всегда спрашивает.
- **Суб-агенты** — встроенные `general-purpose`, `explore`, `plan`, `reviewer`, `tester` и свои из `.memucode/agents/`. `/agents` — список и создание. Сам агент запускает их, только когда вы об этом попросили («используй агентов», «параллельно», «в фоне»): так задаёт настройка `subagents` = `ask`. `auto` разрешает запускать по своему усмотрению, `off` запрещает; меняется в `/settings`.
- **Стили ответов** — `/output-style`: обычный, объясняющий, обучающий, краткий или свой.
- **Хуки** — команды на событиях агента (`PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop` и другие) в формате Claude Code; `/hooks` показывает подключённые.

## MCP

MemuCode подключает серверы Model Context Protocol из настроек MCP в MemuAI (они общие с MemuCode в приложении) и из `.mcp.json` доверенного проекта — запускаемые командой или доступные по адресу HTTP. Инструменты серверов называются `mcp__сервер__инструмент`. `/mcp` — список, добавление, включение, перезапуск; `memucode mcp` — то же без интерфейса.

## Без интерфейса

Для скриптов и CI:

```
memucode -p "найди и исправь падающий тест" --output-format json
git diff | memucode -p "напиши сообщение коммита"
```

`--output-format stream-json` выдаёт события построчно. Каждый вызов инструмента читается мягко: лишняя кавычка, сырой перевод строки или запятая в конце в JSON вызова исправляются и сообщаются, а большие файлы идут блоками `@content:N`, так что длинный файл больше не падает с «not valid JSON». Другие флаги: `-m` модель, `--permission-mode`, `--allowedTools`, `--disallowedTools`, `--add-dir`, `--cwd`, `--max-turns`, `--system-prompt`, `--append-system-prompt`, `--effort`. Без интерфейса действия, требующие подтверждения, отклоняются, если их не разрешают правила или режим. Подкоманды: `doctor`, `models`, `sessions`, `mcp`, `config`, `schedule`, `install`, `uninstall`, `version`.

## Размышления и ход работы

Пока модель работает, строка состояния говорит, что происходит: подключение, ожидание первого токена, размышление, ответ, подготовка вызова инструмента (с размером большого блока, который пишется). Модель, которая стримит рассуждения, показывает **Thinking…** — нажмите на него (или ++Alt+R++), чтобы прочитать рассуждения, и ещё раз, чтобы закрыть; модель без стриминга говорит об этом, а не молчит.

**Скорость (`tok/s`)** показывается только когда её можно честно измерить: текст должен приходить по частям в течение хотя бы полутора секунд. Скорость считается по последним секундам *этого* запроса. Модель, которая держит весь ответ и отдаёт его одним куском, скорости не получает — делить такой кусок на время до него было бы выдумкой (раньше это давало тысячи токенов в секунду).

**Нечитаемые вызовы инструментов.** Если модель записала вызов с ошибкой (не закрыта скобка, вместо `:` стоит запятая, ссылка `@content` без блока, лишняя запись в списке), MemuCode понимает его сам, а в ленте остаётся спокойная строка «Resent a tool call» вместо красной ошибки. Если вызов всё же прочитать нельзя, модель получает точное объяснение, что не так и как написать правильно, а после третьей такой попытки подряд — прямое требование упростить; после шестой работа останавливается с понятной причиной, вместо того чтобы расходовать лимиты.

## Настройки

`/settings` открывает все настройки со списком значений. Настройки хранятся слоями, следующий главнее предыдущего:

| Файл | Для чего |
| --- | --- |
| `%APPDATA%\MemuAI\memucode\settings.json` | ваши личные настройки |
| `.memucode/settings.json` | общие настройки проекта, их можно коммитить |
| `.memucode/settings.local.json` | ваши настройки этого проекта, автоматически добавляются в `.gitignore` |
| флаги командной строки | только на этот запуск |

Ключи API и подключения хранятся только в личном файле: из проектных файлов они игнорируются с предупреждением. Из командной строки: `memucode config list`, `get`, `set`, `unset`.

## Безопасность

- Команды выполняются в песочнице — объекте заданий Windows с ограничением памяти; секреты из переменных окружения в неё не попадают. Остановка агента завершает всё дерево процессов.
- Агент работает только в папке проекта и папках из `/add-dir`; выход за них спрашивается.
- Ключи, токены и cookie не выводятся на экран и не пишутся в журналы, в `/settings` они замаскированы.
- Отчёт `/bug` сохраняется в папку «Загрузки\MemuAI»: ключи в нём замаскированы, текст разговоров туда не попадает.

## Если что-то не работает

| Проблема | Что сделать |
| --- | --- |
| «Proxy не отвечает» | запустите MemuAI или `/proxy`; для работы без Proxy — `/proxy add` |
| ++Shift+Enter++ отправляет сообщение | `/terminal-setup`; всегда работают ++Alt+Enter++ и `\` в конце строки |
| нет цвета или рамки «ломаются» | используйте Windows Terminal; `/theme` → вариант ANSI для старых консолей |
| неизвестна стоимость модели | `/cost refresh` или `/cost set` |
| команда `memucode` не найдена | откройте новый терминал после установки или выполните `/install` |
| кончились лимиты модели | `/auto-continue auto` (или `18:30`, `+2h`) — MemuCode продолжит сам, окно оставьте открытым |

Подробная диагностика — `/doctor`. См. также: [MemuCode](doc:memucode), [MemuAI Proxy](doc:proxy), [Браузер и компьютер](doc:browser-computer), [Решение проблем](doc:troubleshooting).
