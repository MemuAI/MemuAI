# ИИ-пакет: модуль руками ИИ

Модуль можно не писать самому. **ИИ-пакет** — это один текстовый файл, в котором собрано всё, что нужно любому ИИ-агенту (MemuAI, MemuCode, ChatGPT, Claude и т. д.), чтобы написать рабочий модуль с первого раза.

```memu-widget
ai-pack
```

## Что внутри пакета

Пакет собирается в момент скачивания из кода вашей версии MemuAI, поэтому никогда не устаревает:

- **инструкции для ИИ** — в каком виде прислать файлы и чего делать нельзя;
- **справочник моста `Memu`** — все методы с таймаутами и разрешениями, события, атрибуты перевода, классы `mu-*` и токены оформления;
- **правила песочницы** — Content-Security-Policy документа модуля, лимиты размеров и полей манифеста;
- **вся документация группы «Модули»** — включая страницы, добавленные позже;
- **рабочие примеры** — заметки, мини-чат с моделью и краткое содержание документа — и шаблоны мастера;
- **типичные ошибки** и **чек-лист** перед отправкой;
- **тестовый стенд** `memu-module-test.js` (в полном варианте).

| Вариант | Для чего |
|---|---|
| Полный | ИИ-агенту, который умеет запускать код: он сам проверит модуль стендом |
| Компактный | Обычному чату: файл почти вдвое меньше, стенда внутри нет |

Язык пакета (RU или EN) влияет только на пояснения: модуль в любом случае получает переводы на оба языка.

## Как пользоваться

1. Скачайте пакет кнопкой выше.
2. Приложите файл к ИИ-агенту и напишите, например: «Сделай модуль MemuAI — трекер привычек с напоминаниями. Инструкции в файле».
3. Скопируйте ответ целиком и вставьте его в **Настройки → Модули → Импорт → Проверить и импортировать**.
4. Если проверка нашла ошибки, нажмите «Отчёт для ИИ» и отправьте отчёт агенту — он исправит файлы.
5. Когда ошибок нет, нажмите «Импортировать». Модуль появится в списке, его можно сразу открыть или доработать в [мастерской](doc:modules-workbench).

> [!TIP]
> Можно попросить и саму MemuAI: приложите пакет к сообщению в обычном чате.

## Проверить и импортировать

Карточка на вкладке **Импорт** принимает пакет в любом виде:

- **ответ ИИ** — файлы в блоках кода, имя файла над блоком или в его заголовке (`manifest.json`, `index.html`, `style.css`, `main.js`, `i18n.json`);
- **JSON-пакет** `.memu-module.json` (экспорт из MemuAI);
- **ZIP** с папкой модуля — файлы могут лежать во вложенной папке;
- **папку** модуля целиком.

Проверка идёт по тем же правилам, по которым MemuAI запускает модули: идентификатор и манифест, разрешения и вызовы моста, синтаксис JavaScript, запреты песочницы (сеть, `eval`, внешние скрипты), переводы и лимиты. Результат делится на **ошибки** (импорт закрыт), **предупреждения** и **подсказки**, у каждой строки — файл и номер строки.

## Тестовый стенд

`memu-module-test.js` запускает `main.js` модуля без MemuAI: внутри настоящий мост `Memu` из вашей версии и макеты ответов модели. Нужен Node.js 18 или новее, пакеты не требуются.

```bash
node memu-module-test.js ./my-module --click-all
node memu-module-test.js my-module.zip --lang en --theme light
node memu-module-test.js my.memu-module.json --fail-network --json
```

Код выхода `0` — ошибок нет, `1` — найдены ошибки, `2` — пакет не прочитан. Та же проверка без запуска кода доступна из исходников: `python -m app.modules_validate путь`.

## Если что-то пошло не так

- **«Не найден блок manifest.json»** — ИИ прислал файлы без имён. Попросите прислать каждый файл отдельным блоком кода с именем над ним.
- **Идентификатор занят** — укажите новый в поле «Новый идентификатор» ниже на той же вкладке.
- Остальные случаи — в разделе [Модули: решение проблем](doc:modules-troubleshooting).
