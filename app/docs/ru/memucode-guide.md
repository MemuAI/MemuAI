# Эффективная работа с MemuCode CLI

[MemuCode CLI](doc:memucode-cli) — справочник команд, хоткеев и настроек. Этот гайд — о другом: как выстроить работу так, чтобы агент приносил максимум и не тратил ни ваших нервов, ни токенов. Приёмы универсальны — от одиночной правки до долгих целей и CI.

## Начните с памяти проекта

Первое, что стоит сделать в новом проекте, — `/init`: MemuCode изучит код и создаст `MEMUCODE.md` с инструкциями для агента (читаются также `AGENTS.md` и `CLAUDE.md`). Дальше память пополняется на лету: `#правило` дописывает правило прямо из разговора, `/memory` открывает файлы для правки.

Держите правила короткими и конкретными — они попадают в каждый запрос:

| Плохо | Хорошо |
| --- | --- |
| «Пиши качественный код» | «Тесты: pytest, запуск — `python -m pytest tests/`» |
| «Следуй лучшим практикам» | «Импорт только абсолютный, от корня пакета `app/`» |
| «Не ломай существующее» | «Не менять миграции в `alembic/versions/` без явного запроса» |

В `@путь` внутри `MEMUCODE.md` можно включать другие файлы — например, общий стиль кода.

> [!TIP]
> Память — не второй README. Правило стоит записывать, только если агент уже ошибся без него: «UI на русском», «перед коммитом запусти `ruff check`». Периодически вычищайте устаревшее через `/memory`.

## Формулируйте задачи как результат

Описывайте, что должно получиться, а не последовательность шагов — агент сам найдёт путь, а вы сможете проверить результат по критериям.

| Слабо | Сильно |
| --- | --- |
| «сделай красиво» | «форма входа: валидация email на клиенте, ошибка под полем, Enter отправляет» |
| «почини тесты» | «`/test`: все падения из-за нового формата дат; почини, чтобы pytest был зелёный» |
| «добавь экспорт» | «экспорт таблицы в CSV кнопкой рядом с фильтром; разделитель — `;`; проверь на пустой таблице» |

Давайте контекст сразу, чтобы агент не искал вслепую:

- `@путь` — файл или папка приложатся к запросу; `@agent-имя` — поручить задачу конкретному суб-агенту;
- ++Alt+V++ (или ++Ctrl+V++) — скриншот из буфера: баги верстки и макеты лучше один раз показать; путь к картинке, вставленный в терминал, тоже станет вложением;
- длинная вставка текста (лог, стектрейс) сворачивается в `[Pasted text #1 +40 lines]` и раскрывается при отправке — не бойтесь вставлять целые логи;
- ++Ctrl+G++ — написать большой запрос во внешнем редакторе;
- `!команда` — выполнить команду самому, без модели: вывод попадёт в разговор как контекст.

## Режимы: сначала план, потом правки

Режим меняется ++Shift+Tab++ или `/permissions`. Главное — выбирать осознанно:

| Режим | Когда использовать |
| --- | --- |
| План (`/plan <задача>`) | большая или неочевидная задача: агент только исследует код и предлагает план на согласование — дешевле поправить план, чем переделывать правки |
| Обычный | разовые задачи; каждая правка и команда под подтверждением |
| Принимать правки (`acceptEdits`) | долгая серия правок в знакомом коде: файлы правятся без вопросов, команды — с подтверждением |
| Авто | доверяете модели решений: безопасные действия идут сами, рискованные спрашивают |
| Без вопросов (`bypassPermissions`) | **только** контейнеры, песочницы и одноразовые машины — например, headless-прогоны в CI |

Типичный ритм для большой задачи: план → согласовали → `acceptEdits` → работа → `/diff` и `/review` перед коммитом.

## Итерируйте короткими шагами

Один ответ агента — одна обозримая порция работы. Так откат дешёв, а контекст не пухнет.

- `/diff` — незакоммиченные изменения и правки этой сессии; смотрите их, а не верьте на слово;
- ++Esc++ — остановить агента, пока он не ушёл не туда; ++Esc++ ++Esc++ — `/rewind`: откатить код, разговор или и то и другое к выбранному сообщению;
- `/undo` — отменить правки последнего ответа; `/branch` — ответвить разговор и попробовать другой путь, не теряя текущий;
- `/context` — чем занят контекст; `/compact <на чём сосредоточиться>` — сжать историю вручную до того, как она сжалась сама (автоматически — на пороге 85%);
- `/clear` — новая задача, не связанная с предыдущей: начинайте новый разговор, а не тащите всё в одном.

> [!TIP]
> Если правка пошла не так, дешевле откатиться (++Esc++ ++Esc++) и переформулировать задачу, чем «докручивать» неудачный результат следующими сообщениями.

## Параллельная работа

Пока основной разговор занят, независимую задачу можно отдать в фон:

- `/subtask <задача>` (он же `/background`, `/bg` или префикс `&задача`) — отдельный агент работает параллельно, результат приходит заметкой в разговор;
- `/tasks` — список фоновых задач и команд: вывод, остановка;
- агент запускает суб-агентов и сам, инструментом `Task`: несколько вызовов за один ход выполняются параллельно, поэтому «исследуй три модуля» дешевле просить одним сообщением, а не тремя;
- долгие команды (серверы, сборка, прогон тестов) запускаются фоном через `Bash` с `run_in_background`, а их вывод агент читает через `BashOutput` — терминал не блокируется.

Классический пример: вы с основной моделью доделываете функционал, а `&напиши раздел документации по новым командам` трудится рядом — к концу правок документация уже готова.

### Модель суб-агентов

`/agents` выбирает **одну модель для всех суб-агентов** (или наследование основной). Если фоновые задачи простые — поиск по коду, черновики, документация, — поставьте туда дешёвую быструю модель: основная модель останется сильной, а фон подешевеет. Для сложных суб-агентов (`reviewer`, параллельный рефакторинг) оставляйте сильную.

## Долгие цели: /goal

`/goal <цель>` — агент работает шаг за шагом и сам себя продолжает, пока цель не достигнута или не упрётся в препятствие (по умолчанию до 10 продолжений, `--max N` меняет лимит). Цель формулируйте проверяемо: не «улучшить покрытие», а «все тесты зелёные и покрытие `app/core` не ниже 80%». Управление: `/goal status`, `/goal pause`, `/goal continue`, `/goal clear`. Достижение цели проверяет модель решений (`/decisions`), так что «готово на глаз» не пройдёт.

## Спросить, не мешая работе

`/btw <вопрос>` — быстрый вопрос по ходу дела: агент не прерывается, ответ не попадает в историю и не жжёт контекст. «/btw какая версия Python у проекта?» — ровно тот случай.

## Разрешения и правила

Частые подтверждения лечатся правилами: в окне подтверждения ответьте «да, и больше не спрашивать» — MemuCode предложит правило. Список и правка — `/permissions`.

| Правило | Эффект |
| --- | --- |
| `Bash(npm test:*)` | разрешает команды, начинающиеся с `npm test` |
| `Edit(src/**)` | разрешает правки внутри `src` |
| `WebFetch(domain:docs.python.org)` | разрешает читать этот сайт |
| `mcp__github` | разрешает все инструменты MCP-сервера `github` |

Начните с тестов и сборки (`Bash(pytest:*)`, `Bash(npm run build:*)`) и папок, которые агент правит постоянно. Запреты главнее разрешений, составные команды проверяются по частям.

## Скиллы и кастомные команды

Повторяющиеся плейбуки не пересказывают каждый раз, а сохраняют:

- **Скиллы** — `.memucode/skills/<имя>/SKILL.md` в проекте, личные или из `.claude/skills/`. Агент подключает подходящий сам; `/skills` — список, просмотр и создание; `/имя-скилла` — вызов вручную. Хороший скилл: «релиз», «миграция БД», «оформление PR по нашему шаблону».
- **Кастомные команды** — Markdown-файлы в `.memucode/commands/` (подходят и `.claude/commands/`), вызываются как `/имя-файла`. В тексте работают `$ARGUMENTS` и `$1`…`$9`: файл `fix-issue.md` с текстом «Найди issue #$1 и исправь» превращается в `/fix-issue 42`.

## MCP: внешние инструменты

MCP-сервер нужен, когда агенту важен внешний сервис — GitHub, база данных, трекер. Добавление: `/mcp` → «＋ Добавить сервер» (команда stdio или HTTP-адрес) либо без интерфейса:

```
memucode mcp add <имя> -- <команда> [аргументы…]
```

Инструменты серверов называются `mcp__сервер__инструмент`; их можно сразу разрешить правилом. Проектный `.mcp.json` работает только в доверенной папке.

## Модель и глубина размышлений

`/model` (++Alt+P++) выбирает модель, `/effort` (`auto`, `minimal`, `low`, `medium`, `high`, `max`) — насколько глубоко она рассуждает, ++Alt+T++ включает и выключает размышления. Правило простое: лёгкие правки и вопросы — низкая глубина, архитектура и трудные баги — высокая.

Как это доходит до моделей через MemuAI Proxy:

- **Claude из Antigravity** думают по бюджету токенов, и `/effort` его задаёт: `low` — 2048, `medium` — 8192, `high` — 16384, `max` — 32000, `minimal` выключает размышления;
- **Gemini** уровень размышлений имеет в самом имени — выбирайте модель `…-low`, `…-medium` или `…-high` (у 3.1 Pro два уровня: `-low` и `-high`); у Gemini 3.7 и 3.8 Flash три уровня (`…-flash-low`, `-medium`, `-high`), а имя без уровня слушается `/effort` или оставляет выбор Google;
- ответ на языке вашего сообщения приходит при любом выборе — интерфейс остаётся английским, а разговор идёт на вашем языке.

Подробности об именах моделей — в разделе [Аккаунты](doc:accounts).

## Стоимость и токены

- `/usage` — токены по моделям, время, запросы, примерная стоимость сессии, расход за сегодня и 30 дней, лимиты аккаунтов;
- `/cost` — стоимость по моделям; `/cost prices` — откуда взята цена, `/cost set` — свои цены;
- клик по метрике в футере переключает её: цена → токены → время → число инструментов → выкл. Держите под глазами то, за чем следите.

Экономия без потери качества: `/model auto` (простые запросы — быстрой модели), дешёвая модель суб-агентов (`/agents`), `/compact` до автоматического сжатия и короткие сессии вместо одной бесконечной.

## Headless и CI

Без интерфейса MemuCode — обычный скриптовый инструмент:

```
memucode -p "найди и исправь падающий тест" --output-format json
git diff | memucode -p "напиши сообщение коммита"
memucode -c -p "продолжи: допиши тесты на новые случаи"
```

`--output-format stream-json` выдаёт события построчно — удобно для логов пайплайна. `memucode -c` продолжает последний разговор проекта: несколько шагов CI могут работать как одна сессия. Полезные флаги: `-m` (модель), `--permission-mode`, `--allowedTools`/`--disallowedTools`, `--max-turns`, `--append-system-prompt`. Помните: без интерфейса действия, требующие подтверждения, отклоняются — заранее пропишите правила разрешений или (в контейнере) `--permission-mode bypassPermissions`.

## Главные горячие клавиши

| Клавиши | Действие |
| --- | --- |
| ++Shift+Tab++ | сменить режим разрешений |
| ++Esc++ | остановить агента |
| ++Esc++ ++Esc++ | откат к прошлому сообщению (`/rewind`) |
| ++Ctrl+T++ | список задач агента |
| ++Ctrl+O++ | подробный вывод инструментов |
| ++Ctrl+R++ | поиск по истории запросов |
| ++Ctrl+G++ | запрос во внешнем редакторе |
| ++Alt+V++ / ++Ctrl+V++ | вставить картинку из буфера |
| ++Alt+P++ / ++Alt+T++ | выбор модели / размышления вкл-выкл |
| ++?++ на пустой строке | подсказка по клавишам |

Полная таблица — в [MemuCode CLI](doc:memucode-cli).

## Частые ошибки новичков

| Ошибка | Как надо |
| --- | --- |
| «Сделай красиво» без критериев | описывать результат и способ проверки |
| Одна гигантская сессия на всё | `/clear` между несвязанными задачами, `/compact` в долгой |
| Принимать правки не глядя | `/diff` после каждого заметного шага, `/review` перед коммитом |
| Проверять код глазами | просить агента запустить тесты: `/test`, или правило «после правок запускай pytest» в `MEMUCODE.md` |
| Докручивать неудачную правку сообщениями | ++Esc++ ++Esc++ и переформулировать задачу |
| Большую задачу — сразу в правки | сначала план: `/plan` или режим «План» |
| Всё делать последовательно | независимое — в `/subtask`, исследование — параллельными `Task` |
| Режим «без вопросов» на рабочей машине | он только для контейнеров и одноразовых сред |
| Копить правила в `MEMUCODE.md` годами | периодически чистить: каждый пункт стоит токенов в каждом запросе |

См. также: [MemuCode CLI](doc:memucode-cli), [MemuCode](doc:memucode).
